DecideHer — AI Decision Executive

Overview

Built at the AI.WOMEN Hackathon 2026 (AI.Hamburg) with a 5-person, all-women team, DecideHer is an "AI Decision Executive" — a tool that doesn't just score incoming AI and improvement ideas and wave them through. It reads them against company context, clusters related requests, and forces thin evidence through a deterministic gate before anything gets greenlit.

Problem

Companies collect AI ideas one request at a time, and the decision almost never carries the context behind the request. Sales wants "an AI customer agent," Marketing wants an "AI customer-data assistant," Customer Success wants "AI history search" — three AI projects, or one fragmented customer-information problem? Our hackathon scope was a working decision loop, not a full enterprise transformation platform.

Approach

DecideHer is one decision loop, not a scoring model: context → ideas → analysis → decision → clarification. It ingests the company's existing IT landscape, takes in idea submissions as structured intake, clusters and analyzes them against that context, surfaces the result as a findings dashboard, and — when the evidence behind an idea is too thin — asks only the smallest question needed to complete, challenge or reconcile it, rather than inventing confidence.

AI interprets, Anymize protects, deterministic rules keep the decision honest:

Anymize.AI — Privacy PII stripped before model calls, restored only where needed
Gemini API — Understand Free-text submissions → root cause, capability, data object, traceable findings
Deterministic Rules — Evidence Gate Checks required fields, confidence and supplied systems; forces INVESTIGATE when evidence is thin
Gemini API — Clarify Generates only the questions needed to complete, challenge or reconcile missing evidence

AI-powered: interpretation · derived fields · clarification questions  ·  Rule-based: evidence gate · validation · UI/data flow

What Makes It Different

Most AI idea tools help you build the request. DecideHer challenges whether the request is right. The obvious path — idea arrives, AI scores it, build/buy — is fast but premature: the proposed solution becomes the unit of decision before anyone asks whether several ideas share the same problem, whether the company already owns the capability, or whether the evidence is contradictory. DecideHer instead asks context first (what do we already own?), cluster before judge (what's the shared underlying need?), and ask before confidence (what evidence would change the decision?) — so a request can collapse into a shared initiative, reuse an existing capability, or stay flagged INVESTIGATE until the evidence is good enough. The AI is deliberately allowed to say "not enough evidence yet."

My Contribution

This was built as part of a 5-person team (process/operations, product leadership, security/AI governance, data engineering/BI, and software/LLMs) over a 2-day hackathon. My focus was software and LLMs:

  • Built the core decision pipeline (the Streamlit app's intake, clustering and evidence-gate flow) that turns raw idea submissions into structured findings.
  • Integrated the Gemini API for the "Understand" stage — converting free-text submissions into root cause, capability and data-object fields.
  • Implemented the AI clarification logic that generates targeted follow-up questions only when the evidence gate flags a submission as incomplete or contradictory.

Results

Delivered a working core loop by hand-in — context intake, idea capture, analysis and the findings dashboard, plus the evidence-clarification loop (needs-more-info → update → re-analyze). A representative run clustered 15 submitted ideas into 6 initiatives, surfaced 3 cross-team patterns, and flagged 2 ideas as needing clarification. Side-by-side idea-level and initiative-level dashboard views were still a stretch goal at submission time.

Challenges / Learnings

  • Went through several full reframes in 48 hours before landing on the buildable core.
  • Designing an evidence gate that fails closed — forcing an explicit INVESTIGATE state instead of letting the model bluff past thin evidence.
  • Stripping PII before any model call, with a local fallback when the Anymize API wasn't configured.
  • Coordinating a 5-person team spanning process, product, security and data backgrounds.
